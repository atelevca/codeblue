# Подключение UI: контракт API

База: `http://localhost:5089`. Аутентификации нет, CORS не настроен — если UI живёт на
другом порту, его придётся добавить в `Program.cs`.

Все идентификаторы — GUID в каноническом виде. Весь JSON в camelCase.
Статусы приходят **строками**, не числами.

## Общая картина

```
GET  /profiles                        типы записей для выпадашки
POST /files                           фаза 1: загрузить файл, получить fileId
POST /jobs                            фаза 2: оформить запись → запускается обработка
GET  /jobs                            список записей
GET  /jobs/{id}                       карточка + прогресс  ← опрашивать здесь
GET  /jobs/{id}/result                транскрипт со спикерами
POST /document/save/{id}              пересобрать протокол или сохранить правки
GET  /document/get/{id}               прочитать сохранённый протокол
GET  /document/downloadpdf/{id}       скачать протокол в PDF
POST /audio/correctTranscript         перекоррекция готового файла (служебное)
```

Идентификатор один на всё: `fileId`, возвращённый загрузкой, он же id записи, он же
`jobId` в путях документа.

---

## 1. `GET /profiles`

Заполняет выпадашку «тип записи». Вызывать при открытии формы загрузки.

```json
[
  { "key": "administrative", "displayName": "Административная запись" },
  { "key": "financial",      "displayName": "Финансовая запись" },
  { "key": "medical",        "displayName": "Медицинская запись" }
]
```

`key` — то, что потом уходит в `discussionType`. Не зашивайте список в UI: он берётся
из конфигурации сервера.

## 2. `POST /files` — загрузка

`multipart/form-data`, единственное поле `file`.

```
POST /files
Content-Type: multipart/form-data

file: <бинарные данные>
```

Ответ `200`:

```json
{
  "fileId": "ca28c632-3f20-4bea-86b2-1be352013b0a",
  "fileName": "Medpark_audio_2min.m4a",
  "sizeBytes": 1961170,
  "format": "mov,mp4,m4a,3gp,3g2,mj2",
  "durationSec": 120
}
```

Обработка **не запускается**. Файл разобран через ffprobe, поэтому длительность и
формат можно показать в форме сразу.

- `format` — это список синонимов контейнера от ffprobe, как есть. Для показа
  пользователю берите первый элемент до запятой либо своё название по расширению.
- `durationSec` — дробное число секунд; `0`, если контейнер длительность не сообщил.
- Лимит размера — 1 ГБ (`Uploads:MaxBytes`).

Ошибки: `422` — файл не аудио или пуст (проверяется по содержимому, не по расширению);
`503` — недоступен ffmpeg.

## 3. `POST /jobs` — оформление записи

Именно этот запрос запускает конвейер. Тело JSON:

```json
{
  "fileId": "ca28c632-3f20-4bea-86b2-1be352013b0a",
  "title": "Vizită ATI — 26 sept",
  "speakersCount": 4,
  "discussionType": "medical"
}
```

| Поле | Обязательно | Замечания |
|---|---|---|
| `fileId` | да | из ответа `POST /files` |
| `title` | нет | пустой или из пробелов → подставится имя файла |
| `speakersCount` | нет | целое 1..20 или `null` |
| `discussionType` | да | один из `key` от `GET /profiles` |

Ответ `200` — сразу карточка записи, ждать обработки не нужно (см. раздел 4).

Ошибки:

| Код | Когда |
|---|---|
| `400` | неизвестный `discussionType` (в `detail` перечислены допустимые) |
| `400` | `speakersCount` вне 1..20 |
| `404` | `fileId` не найден или его файл исчез с диска |
| `409` | по этому файлу запись уже оформлена |

**`speakersCount` сейчас ни на что не влияет.** Поле принимается, хранится и
отдаётся обратно, но число говорящих диаризация определяет сама. Подписывайте его в
форме как «сколько человек на записи», а не как «сколько показать».

## 4. `GET /jobs/{id}` — карточка и прогресс

Главный эндпоинт для UI: опрашивайте его, пока запись обрабатывается.

```json
{
  "id": "ca28c632-3f20-4bea-86b2-1be352013b0a",
  "fileName": "Medpark_audio_2min.m4a",
  "profileKey": "medical",
  "status": "Running",
  "currentStep": "Распознавание: чанк 3 из 7",
  "percent": 32,
  "workflowId": "bd42e513-6f0b-46ff-81fa-74e7b9765add",
  "error": null,
  "createdAt": "2026-09-26T13:41:20.409+00:00",
  "completedAt": null,
  "sizeBytes": 1961170,
  "format": "mov,mp4,m4a,3gp,3g2,mj2",
  "durationSec": 120,
  "title": "Vizită ATI — 26 sept",
  "speakersCount": 4
}
```

Статусы:

| Значение | Что показывать |
|---|---|
| `Uploaded` | файл загружен, запись не оформлена. В списке не появляется |
| `Pending` | поставлена в обработку, шаги ещё не начались |
| `Running` | идёт обработка, смотрите `percent` и `currentStep` |
| `Completed` | готово, доступен результат |
| `Failed` | упало, причина в `error` |

Про прогресс:

- `percent` — от 0 до 100, **никогда не уменьшается**.
- `currentStep` — человекочитаемая подпись, её можно показывать как есть. Внутри трёх
  долгих шагов она уточняется: `«Распознавание: чанк 3 из 7»`, `«Коррекция терминов:
  батч 2 из 5»`, `«Генерация протокола: составление документа»`.
- Проценты условные, распределены по весу шагов:

  | Шаг | `percent` по завершении |
  |---|---|
  | нормализация аудио | 5 |
  | подготовка входа для моделей | 10 |
  | поиск речи (VAD) | 15 |
  | распознавание | 55 |
  | разделение по говорящим | 75 |
  | выравнивание по говорящим | 78 |
  | коррекция терминов | 90 |
  | сохранение результата | 92 |
  | генерация протокола | 100 |

  Последний шаг — самый долгий после распознавания, поэтому внутри своей полосы он
  докладывает фазы: 92 извлечение фактов, 94 составление документа, 98 сверка.
- `workflowId` — внутренний, UI он не нужен.

Опрашивать раз в 2–3 секунды более чем достаточно: шаги длятся минутами.

`404`, если записи нет.

## 5. `GET /jobs` — список

Массив таких же карточек, новые сверху. Записи в статусе `Uploaded` **не показываются**:
это ещё не записи, а загруженные файлы, по которым не заполнили форму.

Постраничности нет — на прототипе список небольшой.

## 6. `GET /jobs/{id}/result` — транскрипт

Доступен после `Completed`. До этого `404`.

```json
{
  "fileName": "Medpark_audio_2min.wav",
  "durationSeconds": 120,
  "speakers": ["Speaker 1", "Speaker 2"],
  "turns": [
    {
      "start": 0.32,
      "end": 14.8,
      "startTime": "00:00",
      "endTime": "00:14",
      "speaker": "Speaker 1",
      "text": "Pacientul 48, a fost pe data de...",
      "lowConfidence": [
        { "at": 10, "word": "48,", "p": 0.37 },
        { "at": 74, "word": "trombeaspirație", "p": 0.48 }
      ]
    }
  ],
  "text": "Speaker 1:\nPacientul 48...\n\nSpeaker 2:\n...",
  "transcriptionMs": 278431,
  "diarizationMs": 15204
}
```

- `turns` — реплики по порядку. `startTime`/`endTime` в `mm:ss` уже готовы к показу,
  минуты не переводятся в часы (`75:30` — нормально).
- `text` — весь диалог одной строкой, если нужно показать «как есть».
- `speakers` — метки в порядке первого появления. Ролей (врач, пациент) нет.
- `lowConfidence` — слова, в которых распознавание было не уверено: `at` — смещение
  в символах внутри `text` этой реплики, `p` — вероятность. Годится, чтобы подсветить
  сомнительные места. **Поле может отсутствовать**, и у реплики, которую переписала
  коррекция терминов, оно пустое: смещения после переписывания недействительны.

## 7. Протокол (MOM)

**Протокол собирается сам, последним шагом обработки.** К моменту, когда запись стала
`Completed`, он уже сохранён — забирайте его через `GET /document/get/{jobId}`, вызывать
генерацию вручную не нужно.

Единственное исключение: если модель не справилась, задание всё равно завершается
`Completed`, а `GET /document/get` отвечает `404`. Тогда протокола просто нет, и его
можно собрать вручную запросом ниже. Показывать кнопку «Сформировать протокол» имеет
смысл именно в этом случае.

### `POST /document/save/{jobId}` без тела — пересобрать

Тот же расчёт, что и в шаге конвейера: извлечение фактов → генерация документа → сверка
с транскриптом. **Занимает 6–10 минут** на процессоре. Ответ приходит по завершении,
прогресса у этого вызова нет (в отличие от шага конвейера, где он виден в `percent`).

Если протокол уже есть, он перезаписывается. Показывайте явное ожидание с
предупреждением о времени, а не крутилку на пять минут.

Ответ `200`:

```json
{
  "jobId": "85cb407e-...",
  "minutesMarkdown": "# Proces-verbal\n## Rezumat\n...",
  "verification": {
    "summary": "Verificarea automată nu a putut fi finalizată...",
    "findings": [],
    "completed": false,
    "isConsistent": false
  },
  "savedAt": "2026-09-26T18:14:02.11+00:00",
  "delta": { "ops": [ ... ] }
}
```

Про `verification` — три состояния, и их нельзя путать:

| `completed` | `isConsistent` | Что это значит |
|---|---|---|
| `true` | `true` | сверка прошла, расхождений не нашла |
| `true` | `false` | сверка прошла и нашла расхождения, они в `findings` |
| `false` | `false` | **сверка не удалась**, документ сохранён как сгенерирован |

`discardedFindings` — сколько находок модель выдала, но подтвердить не смогла: цитата не нашлась
в транскрипте или документе даже без учёта пробелов, регистра и ş/ș, ţ/ț. Сами такие находки не
отдаются. Если это число больше нуля, `isConsistent` = `false`, даже когда `findings` пуст:
документ стоит показать на проверку.

Последний случай — не ошибка и не отказ: документ полноценный, но не проверенный, и
это надо показать пользователю (`summary` содержит готовый текст на румынском).

Элемент `findings`:

```json
{
  "kind": "Contradiction",
  "description": "Объяснение на румынском",
  "transcriptQuote": "точная цитата из транскрипта",
  "documentQuote": "точная цитата из документа",
  "suggestedCorrection": "предложенная правка"
}
```

`kind` — `Unsupported` (утверждение без опоры в транскрипте, `transcriptQuote` может
быть `null`), `Omission` (важное упущено, `documentQuote` может быть `null`),
`Contradiction` (обе цитаты обязательны).

Ошибки: `404` — нет записи; `409` — транскрипция не завершена; `422` — транскрипт
длиннее лимита (`Minutes:MaxTranscriptCharacters`, сейчас 6000 символов; **ничего не
обрезается, длинная запись просто отклоняется**).

### `POST /document/save/{jobId}` с телом — сохранить правки

Документ редактируется в Quill. Отправляйте **полный снимок** `quill.getContents()`,
а не инкрементальную дельту из `text-change`:

```json
{ "delta": { "ops": [ { "insert": "Proces-verbal" }, { "insert": "\n", "attributes": { "header": 1 } } ] } }
```

Лимит тела — 128 КБ. Сохранённое тоже проходит сверку с транскриптом, то есть запрос
снова долгий. `400`, если `delta` отсутствует.

### `GET /document/get/{jobId}`

Тот же объект `SavedDocument`. `404`, если протокол ещё не сохранялся.

### `GET /document/downloadpdf/{jobId}`

`application/pdf`, имя файла `proces-verbal-<jobId>.pdf`. Быстро — рендер по
сохранённому документу, LLM не задействован. `404`, если протокол не сохранён.

## 8. Служебное: `POST /audio/correctTranscript`

```
POST /audio/correctTranscript?jobId=<guid>&fileName=<имя>.speakers.json&profile=medical
```

Прогоняет коррекцию терминов заново по готовому артефакту, не переделывая
распознавание. Нужно, чтобы подбирать глоссарии и промпты; в обычном UI не требуется.

```json
{
  "sourceFile": "Medpark_audio_2min.speakers.json",
  "correctedFile": "Medpark_audio_2min.speakers.corrected.json",
  "reportFile": "Medpark_audio_2min.speakers.medical_corrections.md",
  "segmentCount": 5,
  "accepted": 1,
  "rejected": 0,
  "changes": [ ... ]
}
```

## 9. Ошибки

Все ошибки — `application/problem+json` (RFC 7807):

```json
{
  "type": "https://tools.ietf.org/html/rfc4918#section-11.2",
  "title": "NotAudio",
  "status": 422,
  "detail": "Загруженный файл пуст.",
  "traceId": "00-d5928c5e..."
}
```

`title` — код ошибки (`NotAudio`, `UnknownProfile`, `RecordAlreadyCreated`,
`InvalidRequest`, `InputNotFound`, `FfmpegUnavailable`, `LlmModelNotFound`,
`Document error`), `detail` — текст для человека. **`detail` местами содержит
абсолютные пути сервера** — не показывайте его пользователю дословно, берите по коду
из `title` свой текст.

`traceId` стоит логировать: по нему находится запрос в `logs/healthtech-*.log`.

## 10. Типовой сценарий

```
1. GET  /profiles                     → заполнить выпадашку
2. POST /files                        → показать имя, размер, длительность
3. POST /jobs                         → запись создана
4. GET  /jobs/{id} каждые 2–3 с       → полоса и подпись шага
   пока status ∈ {Pending, Running}
5. status = Completed
   GET  /jobs/{id}/result             → показать диалог
   status = Failed → показать error
6. GET  /document/get/{id}            → протокол уже готов
   404 → предложить POST /document/save/{id} (долго! предупредить)
7. GET  /document/downloadpdf/{id}    → кнопка «Скачать PDF»
```

## 11. Чего ещё нет

Запланировано, но не реализовано — не закладывайтесь:

- `GET /persons` — справочник врачей
- `PUT /jobs/{id}/speakers` — привязка «Speaker 1» → врач
- `GET /jobs/{id}/transcript` — диалог с подставленными именами

Таблицы `Persons` и `SpeakerBindings` в базе уже есть, эндпоинтов пока нет.
Также нет: отмены запущенной обработки, удаления записи, постраничности в списке,
прогресса у ручного `POST /document/save` (у протокола внутри конвейера прогресс есть).
